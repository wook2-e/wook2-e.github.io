JPA · 영속성 컨텍스트바른생각 독립몰

전액 환불했는데 주문 결제상태가 PAID로 남고, 출고에 품목이 배정되지 않음

현상
에러 없이 화면은 「취소」로 보이는데 orders.payment_status만 PAID로 남음. 출고 행은 생기는데 품목 배정은 0건.
원인
재고 증감 쿼리가 @Modifying(clearAutomatically = true)라 영속성 컨텍스트를 통째로 비움. 그 뒤에 고친 엔티티는 준영속이라 값만 바뀌고 UPDATE가 나가지 않음. SQL 로그로 같은 트랜잭션에서 update orders만 빠진 것을 확인.
해결
엔티티 변경을 재고 쿼리보다 앞으로 옮기고, 그 자리에 「이 아래로 엔티티를 고치는 코드를 넣지 않는다」는 경계를 명시.

목 기반 단위 테스트로는 잡히지 않는 결함 — 같은 함정을 두 곳에서 찾아 함께 수정

교환 승인 후 재고는 바뀐 품목에서 빠지는데 주문 항목은 옛 품목 그대로

현상
승인 200, 클레임 COMPLETED, 교환 품목 재고도 차감됐지만 order_item은 빨강 → 파랑으로 바뀌지 않음. 게다가 재고는 승인 한 번에 2개 빠짐.
원인
① OrderItem에 붙은 @Immutable이 변경을 조용히 버림. ② 교환 집행을 고객 서버로 옮기면서 백오피스의 옛 집행 코드를 지우지 않아 두 서버가 같은 재고를 각자 차감.
해결
변경 대상 엔티티에서 @Immutable 제거, 나머지 @Immutable 엔티티 전수 점검. 집행 소유권을 고객 서버 한쪽으로 일원화.

로컬에서 백오피스를 고객 서버에 붙여 재현 → 재고 −2 → −1, 주문 항목 정상 교체 확인

인증 · 경합언베일 독립몰

회원 결제가 가끔 비회원으로 승인되어 ORDER_NOT_FOUND

현상
PG 결제창에서 돌아온 직후 승인 요청이 실패해 「결제가 승인되지 않았습니다」. 재현이 들쭉날쭉.
원인
① 새 문서라 액세스 토큰이 비어 있고, 세션 복구가 끝나기 전에 승인이 Authorization 없이 나감. ② 탭이 여러 개면 리프레시 토큰 회전으로 한쪽 복구가 INVALID_REFRESH_TOKEN으로 실패해 guest로 내려앉음. 서버 로그로 0.16초 차이를 확인.
해결
승인 전 인증 판정 완료를 기다리게 하고, 「비회원 주문 키가 없는데 guest」면 복구 실패한 회원으로 보고 한 번 더 토큰 재발급 후 세션 채택.

되돌릴 수 없는 결제 경로부터 막고, 근본 원인(다중 탭 × 회전 토큰)은 별도 과제로 기록

PG 연동언베일 독립몰

결제창·카드 인증까지 정상인데 마지막 승인만 R122로 거부

현상
KG이니시스가 「Signature 값이 잘못되었습니다」(R122)로 승인 거부. 증상이 결제창 뒤에 나타나 원인이 다른 곳처럼 보임.
원인
결제창 서명은 쿼리스트링 규칙을 지켰지만 승인 서명만 sha256(authToken + timestamp)로 값을 이어붙이고 있었음. 규격은 sha256("authToken=…&timestamp=…").
해결
승인·검증 서명을 규격대로 수정. 같은 폼을 쓰는 망취소 서명도 함께 바로잡음.

한 번도 성공한 적 없던 승인·망취소 경로를 함께 정상화

DB 최종 상태는 멀쩡한데 주문서가 「주문할 상품이 없습니다」

현상
[바로 구매]·결제 전 선택 정리 직후 주문서가 빈 장바구니로 뜸.
원인
주문서 조회는 읽기 복제본, 선택 변경은 라이터로 감. 「전체 해제 → 살 것만 선택」 중 전체 해제만 먼저 복제된 순간을 읽음.
해결
장바구니 결제는 「끄기만」 하도록 바꿔 복제가 늦어도 살 줄이 사라지지 않게 함. 전체 해제가 불가피한 바로 구매만 CART_EMPTY일 때 한 번 재조회.

복제 지연을 없애려 하지 않고, 지연이 있어도 틀릴 수 없는 순서로 재설계
